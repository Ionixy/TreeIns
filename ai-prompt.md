# Промт: сгенерировать дерево целей для GoalTree

Это **исходник** текста, который приложение показывает на экране
«Настройки → Создать дерево через ИИ». Правьте промт здесь.

Человек копирует промт, отдаёт его любому чат-боту, описывает свою цель — и получает
JSON, который вставляет обратно в приложение («Вставить дерево из текста» либо поле
на том же экране). Ничего сохранять в файл при этом не нужно.

## Как это связано с кодом

В `TreeIns.html` тот же текст собирается функцией `buildAiPrompt()`. Часть значений
она **подставляет из констант**, а не хранит словами, — чтобы промт не начал врать
после первого же изменения формата обмена:

| Что подставляется | Откуда |
| --- | --- |
| `"app": "goaltree"` | `SHARE_APP` |
| `"format": 1` | `SHARE_FORMAT` |
| список значений `type` и их эмодзи | `Object.keys(TYPES)`, `TYPES[k].e` |
| список значений `color` | `Object.keys(COLORS)` |
| значения `type`/`color` по умолчанию и в примере | первый ключ `TYPES` / `COLORS` |
| лимиты длины `name`, `goal`, `text`, `description` | `SHARE_LIM` |
| потолок числа узлов | `IMPORT_MAX_NODES` |
| потолок глубины | `IMPORT_MAX_DEPTH` |

Значения в тексте ниже — те, что действуют на момент правки файла; в приложении на их
месте окажется актуальное. Всё остальное — смысловая часть (требования к содержанию,
пример JSON, формат ответа) — в `buildAiPrompt()` перенесено дословно. Меняя текст
здесь, перенесите правку и туда, иначе версии разойдутся.

Файл перечислен в `ASSETS` в `sw.js`, поэтому открывается отдельной ссылкой и
кэшируется вместе с приложением. При изменении `ASSETS` нужно бампнуть `CACHE_NAME`.

---

Ты помогаешь мне спланировать цель и оформить её как дерево задач для приложения
GoalTree. На выходе мне нужен готовый файл дерева в формате JSON, который я
импортирую в приложение.

## МОЯ ЦЕЛЬ

(заполни поля, лишнее удали)

- Цель: ...
- Срок: ...
- Где я сейчас: ...
- Что уже сделано: ...
- Ограничения: ...
- Сколько времени готов(а) уделять: ...

## Что от тебя нужно

Разбей цель на дерево задач и выдай его строго в формате из раздела «Формат файла».

### Требования к содержанию

1. 6–9 веток первого уровня — крупные направления работы, а не отдельные действия.
   Ветки должны покрывать цель целиком: не только «основную» часть, но и то, что
   обычно забывают (деньги, документы, здоровье, сроки, люди, запасной план).
2. В каждой ветке 3–6 подзадач. Максимальная глубина — 3 уровня от корня
   (ветка → подзадача → под-подзадача). Третий уровень использовать только там,
   где он действительно нужен, а не везде.
3. Каждая задача — законченное действие с проверяемым результатом. «Сдать IELTS на
   6.5» — да. «Английский» — нет. Формулировка должна отвечать на вопрос «что именно
   я сделаю и как пойму, что готово».
4. Задачи внутри ветки идут в том порядке, в каком их делают. Если что-то нужно
   начать сильно заранее из-за срока ожидания — скажи об этом в описании.
5. Описание (description) — только там, где оно несёт информацию: конкретная цифра,
   дедлайн, порядок действий, типичная ошибка, где искать. Не пересказывай заголовок
   другими словами. Если сказать нечего — поле просто не добавляй.
6. Всего 35–60 узлов. Меньше — дерево бесполезно, больше — им перестают пользоваться.
7. Отдельной веткой — сроки и контроль: какие даты критичны, что и когда проверять,
   что произойдёт при опоздании.
8. Язык — русский, кроме собственных названий (экзаменов, организаций, программ).

### Про факты

Если цель завязана на внешние правила, даты, экзамены, цены или процедуры — проверь
их в интернете, если есть такая возможность, и укажи в описании, на какой момент
актуальны данные. Если проверить нельзя — не выдумывай конкретные даты и суммы:
напиши, что нужно проверить и где именно (сайт, страница, ведомство). Ошибочный
дедлайн в трекере хуже, чем его отсутствие.

## Формат файла

Ответ — один JSON-объект ровно такой формы:

{
  "app": "goaltree",
  "format": 1,
  "tree": {
    "name": "Короткое название",
    "goal": "Цель одной фразой",
    "type": "oak",
    "color": "green",
    "root": {
      "text": "Цель одной фразой",
      "description": "Одна фраза про горизонт и главное условие успеха.",
      "children": [
        {
          "text": "Название ветки",
          "description": "Зачем эта ветка нужна.",
          "children": [
            { "text": "Задача с описанием", "description": "Конкретика: цифра, срок, порядок действий.", "children": [] },
            { "text": "Задача без описания", "children": [] },
            {
              "text": "Задача с вложенностью",
              "children": [
                { "text": "Под-подзадача", "children": [] }
              ]
            }
          ]
        }
      ]
    }
  }
}

Жёсткие правила:

- "app": "goaltree" и "format": 1 — ровно так, иначе приложение откажется открывать
  дерево.
- Узел — это только text, необязательный description и children. Никаких id,
  completed, pos и прочих полей добавлять не нужно: отметки выполнения расставляет
  владелец дерева сам.
- children есть у каждого узла, у листьев — пустой массив [].
- type — ровно одно из: oak 🌳, pine 🌲, palm 🌴, sakura 🌸, bush 🌿, maple 🍁.
  color — одно из: green, blue, purple, red, orange. Другое значение молча заменится
  на oak / green.
- tree.goal и root.text — одна и та же фраза.
- Ограничения по длине: name ≤ 120 символов (лучше ≤ 30, чтобы влезало в карточку),
  goal ≤ 400, text узла ≤ 200, description ≤ 2000. Лишнее обрезается при импорте.
- Переводы строк внутри текстов не сохраняются — пиши описание одним абзацем.
- Всего не больше 2000 узлов и не глубже 50 уровней.
- Это должен быть валидный JSON: двойные кавычки, никаких комментариев, без висящих
  запятых. Кавычки внутри текста экранируй как \" — или используй «ёлочки».

## Формат ответа

1. Сначала — 5–10 строк: список веток первого уровня и по фразе, что в каждой.
2. Затем — весь JSON одним блоком кода, без сокращений и без «...».
3. В конце — что стоит проверить самому: факты, в которых ты не уверен, и решения,
   которые я должен принять сам.

Ничего больше не добавляй.
